# 实现选择与复用规则

> 状态：当前有效
> 适用范围：V2 后端、博客端、管理端、测试与构建脚本
> 最后校准：2026-07-28
> 对应代码：`MyBlog-springboot-v2/`、`frontend/apps/blog/`、`frontend/apps/admin/`、`.github/workflows/`
> 权威程度：规则

## 能力选择顺序

实现需求时按以下顺序选择，前一项能清晰满足需求时不得继续自定义：

1. 项目已有公共能力、组件、类型、常量和封装。
2. 语言标准库。
3. 框架或平台原生能力。
4. 已安装且适合的依赖。
5. 最小必要的自定义实现。

新增工具、校验、转换或抽象前，先搜索同类实现及全部调用点。标准库、Spring、Vue、浏览器、数据库或现有依赖已经覆盖的能力，不再手写第二套；现有能力确有缺口时，在承担该职责的模块中最小扩展，不创建通用工具堆放区。

## 清晰与边界

- 选择能直接表达当前需求的写法，不为单一实现增加接口、工厂、多层包装、预留配置或未来扩展点。
- 修复问题时定位共享根因，并检查同一能力的其他调用点；不得只在单一页面或 Controller 旁路打补丁。
- 服务端和数据库继续承担权限、约束与业务规则的最终校验。前端可以提供即时反馈，但不得维护会与后端漂移的第二套规则。
- 重复值、枚举和转换只在明确的职责边界内收口；不能为了“复用”把无关业务塞进同一个 helper。
- 新增依赖必须证明项目现有能力和标准方案不足；能用原生 HTML/CSS、框架生命周期、数据库约束或标准库完成时不引入依赖。

## 前端国际化

- 所有用户可见的界面文案、状态、错误提示、空状态、复制提示和动态文案都进入应用现有 i18n 语言包。
- 业务组件不得用 `if`、三元表达式、`navigator.language` 或 locale 字符串比较直接切换文案，也不得在组件内维护平行翻译表。
- 只有日期格式、排版方向等确实随语言改变的行为才允许语言分支；分支使用项目统一的 locale 解析结果，并由测试固定行为。
- 后端提供的三语内容继续使用项目既有字段选择与中文回退规则；界面固定文案不得混入业务数据回退逻辑。

评审时关注是否影响正确性、安全性、可维护性和后续成本，不把纯格式偏好或个人写法差异当作问题。
