## 1. 生产运行与安全收口

- 维持每周 MySQL 逻辑备份、私有 S3 生命周期和 timer 成功记录（ISSUE-002）。个人博客不做自动回滚或生产应用回退演练；数据库恢复仅在迁移前或真实故障时于隔离环境单独验证。
- Caddy 基础安全响应头已按传输层、静态站点和 API 责任拆分，并由真实 Caddy/模拟上游 CI 验收；`main` 合并提交 `30d75ee1` 已完成同 SHA 部署和独立生产检查。随后单独设计有效的 CSP Report-Only 报告链路，完成真实浏览器回归后再收紧（ISSUE-024）。
- Cookie 化属于独立认证专项：先固定 CSRF、CORS、会话恢复与本地开发契约，再迁移 refresh token（ISSUE-005）。

## 2. 管理端统计与列表管理优化（实施草稿）

[`ISSUE-023`](open-issues.md) 的现有统计表达与本轮确认的分页查询排序已全部完成；其余项目仍按独立阶段实施，不因前述阶段完成而默认进入开发。

1. **现有统计表达收口（已完成）**：当前值统一命名为“页面日 UV 合计”；查询区间与今日指标已分组；趋势、热门文章和语言分布使用局部空态；热门文章可跳转管理端编辑页；图表跟随容器尺寸变化。聚合更新时间仍只有在后端能提供真实聚合完成时间后才展示。
2. **分页查询排序（已完成）**：文章普通列表支持四个白名单字段；评论列表首批只支持创建时间；正常附件库支持上传时间、文件大小和原始文件名；文章回收站首批只支持删除时间。四者 SQL 均保持稳定的 ID 次排序，管理端切换排序后回到第一页。附件回收站保留删除时间倒序。标签是完整集合，可保留前端本地排序；分类和友链的 `sortOrder` 仍是业务展示顺序，不能被查询排序覆盖。
3. **附件引用保护（已完成）**：当前唯一结构化附件 ID 引用为文章封面；删除仍被任何文章记录（含回收站）引用的附件时，后端返回 `409 + 90004` 并拒绝软删除。Markdown 与任意 URL 文本不参与检查，附件卡片布局未重做。
4. **附件管理效率**：文件名、内容类型和时间筛选仍按真实管理需求单独评估。
5. **统计模型增强**：只有明确需要后才评审站点级日 UV、页面类型和访问来源。这些项目涉及采集字段、聚合表、Flyway、历史数据和隐私边界，不能与前述页面优化混合。

每项先完成定向后端与管理端测试，再按受影响范围运行完整后端、管理端 test、typecheck、build 与首屏预算检查。不得预先引入通用排序框架、数据仓库、搜索引擎或新的图表依赖。

## 3. 管理端外壳治理

1. **命令面板（已完成）**：页头入口、实现、配置、三语文案、专属资源及拼音搜索、拖拽排序依赖已经一并移除，业务页面、路由和列表筛选保持不变。
2. **iframe（已完成）**：已移除无业务使用的 iframe 外壳及相关路由处理，并以独立的响应式路由组件交接层保持主体内容切换；自动验证、登录后页面回归、main CI 和同 SHA 生产部署均已通过。打印功能的临时 iframe 保留。
3. **布局、标签页、动态菜单与 strict（后续）**：只在保留交互明确后逐项推进；不在删除外壳前硬修全部 strict 错误。
