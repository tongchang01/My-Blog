# 路线图

> 状态：当前有效
> 适用范围：MyBlog V2 后续实施顺序
> 最后校准：2026-07-30
> 对应代码：`MyBlog-springboot-v2/`、`frontend/apps/`
> 权威程度：路线图

## 1. 生产运行收口

- 按发布检查清单补齐数据库备份恢复、S3 全链路、可信代理、端口边界和应用回滚的演练记录。
- 观察 `main` 的自动部署与公网 HTTPS 冒烟；处理失败时先保留现场和日志，不假定数据库可随镜像自动回滚。

## 2. 公开体验收口

1. 确认并修复博客公开页面标题层级（ISSUE-019 剩余部分；原生交互语义已完成）。

该项为 P1；按可独立验证和回滚的任务实施，不与视觉改版、后台字段或 API 改造混合。

## 3. 管理端统计与列表管理优化（实施草稿）

[`ISSUE-023`](open-issues.md) 的现有统计表达与文章列表排序已完成；其余项目仍按独立阶段实施，不因前两批完成而默认进入开发。

1. **现有统计表达收口（已完成）**：当前值统一命名为“页面日 UV 合计”；查询区间与今日指标已分组；趋势、热门文章和语言分布使用局部空态；热门文章可跳转管理端编辑页；图表跟随容器尺寸变化。聚合更新时间仍只有在后端能提供真实聚合完成时间后才展示。
2. **分页查询排序（文章已完成）**：文章普通列表已按模块内字段白名单和方向枚举实现，SQL 保持稳定的 ID 次排序，管理端切换排序后回到第一页。剩余评论、附件、文章回收站仍按此顺序分别实现。标签是完整集合，可保留前端本地排序；分类和友链的 `sortOrder` 仍是业务展示顺序，不能被查询排序覆盖。
3. **附件管理效率**：在独立任务中评估文件名、内容类型和时间筛选，以及引用状态和删除保护；不因这项工作重做附件卡片布局。
4. **统计模型增强**：只有明确需要后才评审站点级日 UV、页面类型和访问来源。这些项目涉及采集字段、聚合表、Flyway、历史数据和隐私边界，不能与前述页面优化混合。

每项先完成定向后端与管理端测试，再按受影响范围运行完整后端、管理端 test、typecheck、build 与首屏预算检查。不得预先引入通用排序框架、数据仓库、搜索引擎或新的图表依赖。

## 4. 产品增量

优先级由实际使用需求决定：

1. 文章封面对齐位置（ISSUE-018）。
2. 文章上一篇/下一篇导航（ISSUE-008）。
3. Spotify Embed（ISSUE-010）与分享/搜索分发能力。

## 5. 触发式架构扩展

- 多人或更高安全要求触发 HttpOnly Cookie 与 CSRF 设计。
- 明确搜索收录目标后再实现 sitemap、RSS/Atom、Open Graph 和结构化数据。
- 需要横向扩展时再设计共享限流与运行协调；当前单实例 CD 保持 Docker Compose + GHCR 的可迁移边界。

具体完成条件见 `open-issues.md`。
