## ISSUE-002：最小数据备份与运行证据持续维护

- 优先级：P2，运行保障。
- 现状：V2 已运行在 AWS EC2；GitHub OIDC SSH CD、GHCR 同 SHA 镜像发布和三条公开 HTTPS 健康检查均已通过。2026-08-07 起，MySQL 逻辑备份每周日 03:30（JST）写入同一 S3 桶的私有 `recovery/mysql/` 前缀，保留 30 天；首次手工运行已验证对象存在、默认服务端加密、匿名读取被拒绝和本地临时文件清理。
- 已确认方向：个人博客不实现自动回滚，也不安排生产应用回退演练；保留不可变 SHA 的手工回退手册，仅在真实故障时使用。数据库恢复只在发生真实故障或数据库迁移前另行安排隔离环境验证。
- 完成条件：定期检查 timer 最近一次成功结果与 S3 生命周期；修改备份脚本、迁移数据库或出现恢复需求时，单独执行并记录隔离环境恢复验证。敏感资源标识只写入私有生产台账。

## ISSUE-005：管理端 token 存储风险

- 优先级：P2，已确认的安全改造。
- 现状：access/refresh token 存入 `myblog-admin-session` localStorage；XSS 可以读取长期凭证。
- 当前约束：后台不渲染未清洗 HTML，token 不进入 URL、日志或第三方 SDK，refresh 轮换与后端撤销保持启用。
- 已确认方向：refresh token 改为 HttpOnly、Secure、SameSite Cookie，access token 只保留在内存；不得把 Cookie 化与后台瘦身、CSP 或业务功能混在同一任务。
- 完成条件：先完成同源/CORS、CSRF、登录、刷新、退出、改密、本地开发与 DEMO 的契约设计；实现后覆盖 Set-Cookie 属性、轮换、撤销、跨域拒绝和前端会话恢复的后端/管理端测试。

## ISSUE-006：单实例限流不能横向扩展

- 优先级：P3，部署触发。
- 现状：登录失败、评论频率/重复提交和访问打点限流使用 Caffeine，各实例状态不共享。
- 重开条件：部署两个以上后端实例。完成方案需提供共享原子计数、过期、容量、降级和测试，不默认绑定某个中间件。

## ISSUE-008：博客端非阻塞体验补齐

- 优先级：P3，上线后体验优化。
- 现状：文章正文与评论之间的上一篇、下一篇导航尚未恢复，公开文章详情接口也没有返回相邻文章。
- 当前约束：只补相邻文章查询与导航，不借此改作者卡、正文统计或文章详情布局。
- 完成条件：后端按发布时间和 ID 提供相邻文章信息，前端恢复上一篇、下一篇组件。

## ISSUE-010：博客音乐体验

- 优先级：P2，体验增量，非发布阻塞。
- 方向：不恢复旧版权/主题署名页脚，也不把播放器固定在页面末尾。导航栏提供音乐入口；用户主动打开后显示播放面板；仅在有活动播放时显示右下角迷你控制条，以便跨页面暂停、继续或展开。
- 当前约束：播放器的曲目来源、版权/授权、是否需要登录和播放列表管理尚未设计；未明确前不得接入第三方音乐服务或上传媒体文件。默认状态不显示常驻悬浮条，避免干扰文章阅读。
- 完成条件：确定媒体来源与授权边界；完成导航入口、播放面板、跨路由播放状态、活动迷你控制条、移动端布局、键盘可操作性及播放失败状态；通过前端测试和主要页面回归。

## ISSUE-018：文章封面对齐位置缺失

- 优先级：P2，内容展示体验。
- 现状：文章只保存封面附件 ID，博客端卡片和文章详情页背景均按默认中心位置裁剪；主体偏离中心时可能离开可见区域。
- 已确认方向：按 [`ADR-0020`](../adr/0020-article-cover-position.md) 在文章上保存 0–100 的 X/Y 整数百分比，默认 50/50；管理端使用无新增依赖的选点与实际裁剪预览，博客端应用原生 CSS 对齐位置。
- 范围约束：不生成派生图，不引入 Panzoom、Canvas 裁剪器、AI 检测或外部图片服务；不得让 PASSWORD 密码明文或哈希进入任何查询响应。
- 完成条件：使用下一个可用 Flyway 迁移贯通文章完整写入和后台/公开读取；管理端支持完整原图选点、X/Y 控件、单个裁剪预览和重置中心；普通卡片、首页横向卡片与详情页背景均应用位置；后端、管理端、博客端和运行中 API 契约覆盖默认值、边界、越界与完整 PUT。

## ISSUE-019：博客公开页面标题层级不一致

- 优先级：P1，公开阅读可达性。
- 现状：首页文章卡片重复使用 `h1`，文章详情存在两个 `h1`，留言板没有页面级 `h1`。
- 范围约束：先确认首页卡片标题、详情页站点标题与文章标题、留言板主标题的语义策略；不借此改视觉风格，也不回退现有原生链接和按钮语义。
- 完成条件：确认并实现标题策略，使每个公开页面只有一个符合内容层级的 `h1`；首页、筛选结果、搜索、文章详情、留言板和 404 的组件测试及真实浏览器回归通过。

## ISSUE-023：管理端统计与列表管理优化的产品决策

- 优先级：P2，管理体验增量，非发布阻塞。
- 现状：管理端已具备访问统计、文章、评论、附件和回收站等真实查询能力；统计日 UV 目前按文章和语言日聚合后求和。文章普通列表、评论列表、正常附件库与文章回收站均已支持各自确认范围内的服务端白名单排序。当前事实与可验证边界见 `../architecture/`、`../api/`、`../frontend/admin/` 和对应源码。
- 已确认：保留现有 UV 算法并统一命名为“页面日 UV 合计”，暂不新增站点级日 UV。统计第一阶段仅收口现有表达与交互，不加入管理待办、上一周期 PV 对比或缺少真实后端时间的“更新时间”。
- 第一阶段完成：API 文档、OpenAPI 与管理端三语标签已统一口径；查询区间和今日指标分组展示；趋势、热门文章和语言分布使用局部空态；热门文章可进入文章编辑页；趋势图跟随容器尺寸变化。
- 文章排序阶段完成：后台文章列表支持按更新时间、创建时间、发布时间和评论数升降序查询，SQL 使用字段白名单与稳定 ID 次排序；管理端使用服务端排序并在切换时回到第一页。
- 评论排序阶段完成：后台评论列表只允许按创建时间升降序查询，SQL 使用受控方向与稳定 ID 次排序；管理端不对当前页做本地排序。
- 附件排序阶段完成：正常附件库支持按上传时间、文件大小和原始文件名升降序查询，SQL 使用字段白名单与稳定 ID 次排序；管理端保留卡片布局，附件回收站继续按删除时间倒序。
- 文章回收站排序阶段完成：首批只允许按删除时间升降序查询，SQL 使用受控方向与稳定 ID 次排序；管理端不复制普通文章列表的筛选条件。
- 已确认后续：附件管理先做结构化引用状态与删除保护。删除仍被结构化引用的附件必须由后端拒绝；实施前搜索所有结构化引用点，不把 Markdown 或任意公开 URL 文本误判为可追踪引用。
- 后续范围：文件名、内容类型和时间筛选保持独立的管理效率任务；页面类型、访问来源和站点级 UV 继续暂缓，若启动必须单列统计模型与隐私评审。
- 实施草稿：先完成不新增统计表的口径与页面表达收口，再按资源拆分服务端白名单排序；附件管理效率随后独立实施。站点级 UV、页面类型和来源分析涉及采集、聚合、Flyway 与隐私边界，必须单列评审。具体顺序见 `roadmap.md`。
- 完成条件：产品决策逐项确认后，为每个阶段建立独立、可验证、可回滚的任务；不得把前端当前页排序当作分页全局排序，不得把客户端字段直接拼入 SQL，也不得把查询排序写回分类或友链的业务 `sortOrder`。

## ISSUE-024：生产安全响应头与 CSP 未收口

- 优先级：P1，前端信任边界。
- 现状：博客外链脚本、作者简介和评论渲染已分别完成本地化、纯文本与清洗兜底，但 Caddy 尚未设置统一的安全响应头或 CSP。
- 已确认方向：先增加低兼容风险的响应头，再以 CSP Report-Only 采集真实违规；确认主站、`www`、管理端、`/api` 代理、图片、编辑器与三语页面无误后，才收紧为强制 CSP。
- 范围约束：不新增前端安全框架，不将 CSP 写成未经浏览器回归的静态猜测规则；Cookie 化由 ISSUE-005 单独处理。
- 完成条件：Caddy 配置与回归测试覆盖三域、代理和静态资源；浏览器回归确认关键流程可用，Report-Only 无需允许的违规后再启用强制策略。

## ISSUE-025：管理端模板外壳与 strict 治理

- 优先级：P2，可维护性专项。
- 现状：admin 保留命令面板、iframe、多个布局、多标签页和动态菜单等 vue-pure-admin 外壳；`strict` 关闭，严格模式实验曾主要在外壳产生错误。
- 已确认首批：先分别移除命令面板及其专属依赖、iframe 外壳及相关路由处理；每项使用独立 `refactor/*` 分支和提交，完成后执行管理端验证与人工页面回归。
- 后续决策：三套布局、多标签页和动态菜单必须逐项确认保留语义后再删；不得为了分类拖拽重新保留将被命令面板移除的 `sortablejs`。
- 完成条件：首批删除后重新统计 strict 错误、依赖和入口预算；后续仅在保留范围明确后开启 strict 并收紧 `no-explicit-any`。
